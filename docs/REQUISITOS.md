# Matriz de trazabilidad de requisitos

**Proyecto:** Sistema de Gestión de Tarjetas de Crédito, examen técnico para Analista Programador (Crédito Hipotecario Nacional de Guatemala)
**Stack:** SQL Server 2022 (T-SQL) · Spring Boot 3.3 / Java 17 / JPA · Vue 3 + Vite · Keycloak 25 · Docker Compose
**Fuente de verdad:** [REGLAS_CREDITO.md](REGLAS_CREDITO.md); su **Parte 2** (secciones 9 a 15: cuenta de crédito y tarjeta, estabilidad laboral, reposición, reversos y API por cuenta) su **Parte 3** (secciones 16 a 20: código de cliente, RB-04 vigente, permisos por rol, datos sensibles y ajustes de interfaz), su **Parte 4** (secciones 21 a 27: cargos, requisitos y costo de la reposición, renovación, cancelación y ajustes) y su **Parte 5** (secciones 28 a 32: pago mínimo del 10 % e interés automático del 5 %) prevalecen sobre [ARQUITECTURA.md](ARQUITECTURA.md) y sobre las secciones anteriores donde difieran.

Convenciones:
- **RF**: requisito funcional (CLI = clientes, SOL = solicitudes, TAR = cuentas, tarjetas, consumos y pagos, CIC = ciclo de facturación, BLQ = bloqueo, REP = reposición, REV = reverso, CAT = catálogo, SEG = permisos y perfiles, SEN = datos sensibles, UI = ajustes de interfaz, CRG = cargos, REN = renovación, CAN = cancelación, AJU = ajustes de cargos, PAG = pago mínimo y mora, INT = intereses, SEM = datos semilla).
- **RN**: regla de negocio. **RC**: regla de crédito y mora. **RB**: bloqueo. **RR**: reposición. **RV**: reverso. **CA**: cancelación. **RNV**: renovación (corresponde a RN-01 a RN-04 de la sección 23 de REGLAS_CREDITO.md; se renombra para no confundirlo con las reglas de negocio RN-xx de esta matriz). RC, RB, RR, RV y CA según [REGLAS_CREDITO.md](REGLAS_CREDITO.md). **RNF**: requisito no funcional (añadido por el equipo). **RE**: entregable.
- **Capas:** BD, BE (Backend), FE (Frontend).
- **Estado:** *Cumplido* = implementado y localizado en el código; *Cumplido (verificado)* = además comprobado con pruebas unitarias y/o de extremo a extremo contra el stack en Docker con tokens reales de Keycloak (curl y navegador).
- **Evidencia:** archivo, clase, endpoint o prueba donde se cumple el requisito. Las clases de prueba están en `backend/src/test/java/gt/com/chn/tarjetas/`.
- Códigos HTTP: 400 = validación, 404 = no existe, 409 = duplicado o integridad, **422 = regla de negocio**.

Tablas: `dbo.cliente`, `dbo.solicitud_tarjeta`, `dbo.cuenta_credito`, `dbo.tarjeta_credito`, `dbo.consumo`, `dbo.pago` y `dbo.cargo` (BD `GestionTarjetasCredito`).

**Resumen (2026-10-10, con las Partes 4 y 5):** 131 de 132 requisitos cumplidos; `./mvnw test` ejecuta **195 pruebas** en 12 clases sin fallos. Solo queda pendiente RE-01 (publicar el repositorio), que realiza el usuario. La sección 8b agrega los requisitos de las Partes 4 y 5 y la sección 10 confirma que los requisitos del enunciado original siguen cumpliéndose. Desde la Parte 3, la autorización es **por permiso** (sección 8a): donde una fila dice "solo ADMINISTRADOR" o "ADMINISTRADOR y OPERADOR", se refiere a los perfiles que tienen el permiso indicado.
